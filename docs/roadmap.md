# TomoRead 产品路线图

TomoRead 的目标是成为本地优先、可回跳且具备知识整理能力的跨平台阅读器。ColorTxt 与 ReadAny 用作产品行为和架构参考；不会复制其源码、资源、私有协议或文案。

## 当前基线

目前已具备 EPUB、PDF、TXT 和 Markdown 导入；EPUB/PDF 标注、书签与全局笔记；系统/导入字体；TXT/Markdown 显示投影；番茄专注；可信内容检索与阅读助手；本地词云与 AI 思维导图；系统 TTS；关键词与向量混合语义检索；备份/恢复与存储诊断；同步数据模型（版本、墓碑、冲突）；以及多 Provider 的 AI 对话配置。

## 优先级

| 优先级 | 主题 | 交付结果 | 状态 |
| --- | --- | --- | --- |
| P0 | 定位契约与回归样本 | 不同格式在重启、搜索、布局变化后仍可验证地回到原文 | 部分（阅读位置/选区/引用回跳已支持，回归样本待扩充） |
| P0 | 版本化备份、恢复与存储诊断 | 校验后的本地备份、可回滚恢复和安全缓存清理 | 已实现 |
| P0 | 同步数据模型 | 实体版本、删除墓碑和确定的冲突处理，为远程同步建立基础 | 已实现 |
| P1 | WebDAV 手动同步 | 显式触发、可观察、可中断和可恢复的同步 | 未实现 |
| P1 | 系统 TTS | 以阅读 locator 驱动的朗读游标和跨平台降级 | 已实现 |
| P1 | EPUB 交互完善 | 脚注、图片查看以及安全的内外部链接策略 | 已实现 |
| P1 | PDF 文本标注 | 基于页码和矩形选区的标注、导出与 AI 引用 | 已实现 |
| P1 | TXT/Markdown 正文着色 | 在可靠 raw/display 映射上复用现有词条规则 | 已实现 |
| P1 | 文件接入与效率 | 桌面拖放、目录导入、文件关联、移动端分享导入、快捷键和自动滚动 | 已实现 |
| P1 | 向量模型与语义检索 | 可配置的本地/远程 embedding、关键词与向量混合排序，始终保留无模型降级路径 | 已实现 |
| P1 | 设置中心 | 按阅读、书库、AI/向量、数据、同步、快捷键与诊断分组的可搜索配置入口 | 已实现 |

## 依赖顺序

先完成定位契约，再交付备份与同步数据模型；WebDAV 依赖全部 P0。EPUB、PDF、文件接入和阅读效率功能可以在定位基础稳定后并行推进。设置中心先提供分组、导航和安全持久化边界，AI、向量、同步和 TTS 的具体配置随对应能力交付。TTS 使用已解析的 EPUB/TXT/Markdown 内容；PDF 只有在可靠文本定位完成后才接入。语义检索不应成为普通全文搜索的前置条件。

## 不纳入当前路线图

额外电子书格式（MOBI、AZW、FB2、CBZ 等）、在线书源、自动更新、云端多音色 TTS、正文副本编辑及 macOS/iOS 支持不属于当前 P0/P1。在线书源必须先完成版权、地区合规、反爬与凭据隔离评审。WebDAV 同步是当前唯一未交付的 P1 项，其数据契约（版本、墓碑、冲突）已就绪，仅缺远端传输层。

## 交付与验证

每个功能应拆成范围清晰的提交，包含必要的迁移、测试和文档更新。当前开发机可不安装 Flutter；推送后由 GitHub Actions 的 `Verify` 作最终验证，执行 `flutter pub get`、`flutter analyze lib test` 和 `flutter test`。平台构建任务不作为单个功能提交的默认等待条件。
